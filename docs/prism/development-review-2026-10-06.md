## A 总体判断：方向正确，下一步优先改进实验生产流程

**我支持继续 Prism，也支持“先看实战价值，再按行为确定风格路线”。**

这比“训练目标叫 Beta，结果就必须证明自己是 Beta”合理。训练目标是假设，实战行为才是证据。风格目标未达，不该抹掉模型在其他路线的价值。

但要补上后半句：**归类可以灵活，证据标准不能跟着结果移动。** 未呈现 Beta 特征，不等于证明了 Balance；略偏大牌，也不等于已经形成鲜明 Alpha 风格。

| 评审维度 | 当前判断 |
| --- | --- |
| 核心架构 | 实体表示、动作条件读取、玩家信息边界值得保留。本轮未发现推翻架构的理由。 |
| PPO 迭代 | 已有有效实战结果，但不能推断每轮扩量都稳定增强。 |
| 多风格路线 | 可继续研究，但当前分支名称比已证实的风格分化更清晰。 |
| 工程与决策 | 是下一阶段最应优先投入的部分。扩量成本、状态一致性和证据效率都有改进空间。 |

**当前运行快照：2026-10-06 19:22，北京时间。** M67 的 A 完成 5120 局，远端产物审计回执通过；B 完成 3076/5120 局，在第 13 轮。远端流水线进程身份匹配。110000 局独立竞技评测尚未开始，不能提前评价这轮棋力。

## B 架构评审：保留长处，不急着重写

当前结构把牌、玩家、贵族等表示为实体。合法动作通过自身特征、目标实体和全局信息查询这些实体，再输出策略分数。

**做得好的部分：**

- 实体与动作的排列不应改变语义，已有置换一致性测试。
- 规则引擎决定合法动作，网络不必重新学习合法性。
- 训练输入限于玩家可见信息，裁判回放留在审计边界。
- 策略和胜负价值共享表示，风格价值另设训练头。
- Python/Rust 数值校验、精确权重身份和恢复状态有明确约束。
- PPO 已记录 KL、裁剪比例、归一化熵和梯度范数，不能说缺少训练健康检查。

**限制也要说清：**实体间主要经过均值汇聚交换信息，并非完整的实体两两注意力网络。压缩历史也不等于完整记忆。它们是表达能力边界，不是本轮已证明的缺陷。

因此我不建议现在优先加深网络、加记忆或上搜索。先从保存的失败对局证明瓶颈，再做同预算消融。不要把缺乏稳定增益直接归因于模型太小。

## C 下一次扩量前，应先处理的工程问题

### P1：当前扩量还不是高吞吐训练

M67 历史记录中，每个周期都是 256 局，但导出间隔从首轮约 6.97 分钟增至第 15 轮约 46.64 分钟。首轮口径略有不同，这不是函数级计时；它仍足以否定简单线性耗时外推。

学习器的 `minibatch_size=256` 也不意味着一次并行处理 256 个状态。当前实现逐条 forward/backward，再累积梯度。这有助于数值复现，却限制了批处理收益。

代码确认了两类累计开销：每局状态变化会反复提交包含历史尝试的完整账本；每局启动前还会递归扫描训练目录。张量去重不能消除纯字典账本的重复序列化。这些热路径随运行增长，值得先改；具体耗时占比尚未测量。

**建议：**先分别计时采集、推理、审计、序列化、持久化、更新。账本改为追加记录或分片，并用增量容量记账配合定期核对；保留单写者、尝试预算和崩溃恢复语义。然后验证有界并行采集和固定形状微批，不承诺增加硬件就能等比例加速。

### P1：监控与真实运行状态会脱节

本次查询时，原本机观察器 PID 已不存在；原因本次未查明。ALL 最后心跳停留在 16:03，远端却仍在训练 B。A 的旧进度文件还写着采集中，但最终审计已经通过。

**建议：**将远端执行、本机观察、报告交付分成三种状态。完成回执优先于旧进度文件，页面必须显示观察时间与是否过期。观察失败不能停止研究，也不能冒充研究已停止。

### P1：报告失败后缺少正常恢复入口

我在临时目录注入页面渲染失败：最终结果已写入，但部分报告未生成。再次调用报告器，会因“输出已存在”直接拒绝。

**建议：**保留不可变结果，新增只读、可重复的渲染入口。按结果哈希校验已完成输出，只补缺失页面；或先在独立目录生成完整报告包，再原子发布完成清单。不要删除原结果后重新计算，更不该重跑比赛。

## D 实战评审：局数更多，不等于证据更全面

**M67 比过去更严谨。** 它固定最终 c20，分开报告两个训练种子，采用共同种子换座，并校正四项竞争检验。这些都应保留。

但它主要回答：“这两个检查点，在这组固定对手上有没有收益？”它不能独自回答：“这种训练方法普遍稳定有效吗？”

| 问题 | 当前证据边界 | 建议 |
| --- | --- | --- |
| 训练随机性 | 110000 局能提高检查点测量精度，但只有两个训练实例。 | 后续探索优先覆盖更多训练种子，再对预先选定候选做大样本确认。 |
| 对手覆盖 | A 的训练局数占比为 Prism v0.1.1 50%、父代 Prism Alpha v0.1.5 25%、Prism Alpha v0.1.4 与 Prism Beta v0.1.0 各 12.5%。 | 保留历史锚点，再增加训练外的代表策略。新种子不等于新对手分布。 |
| 平均值掩盖退步 | 当前竞争门看共同池均值和直接父代，不自动约束每个代表对手。 | 默认冠军评审可增加少量关键对手的退步容忍规则；不要求所有对手都提高。 |
| 训练模式与使用模式 | 训练采样，默认实战使用 greedy。两者不必同步改善。 | 开发阶段固定观察两种模式，正式结论按实际使用模式出具，禁止混池。 |

“均值掩盖退步”已用合成数据验证，**不是 M67 的实际战绩**。六个对手中，一个下降 50 个百分点，另五个各上升 50 个百分点时，池均值仍可通过增强判断。

M66 已有报告也提醒我们要克制：共同池变化区间跨零，直接父代区间也覆盖 50%。这表示增强尚未确认，不代表无效，更不代表应无限加训直到显著。

**下一轮样本量应先回答要识别多大的提升。** 探索、候选选择、最终确认分开。若采用分阶段扩样，应提前规定停止与错误率控制，不能看结果后临时追加到通过为止。

## E 风格归类：从一个名字，改为一张有证据的画像卡

当前 Prism Beta v0.1.0 的研究路线叫 Beta，但其身份记录明确写着混合、偏得分，尚未建立更强基建倾向。这是诚实的记录，却容易被下游仅读取路线字段时误用。

**建议每个模型独立保存六件事：**精确权重、训练血缘、训练目标、行为画像、路线建议、发布/冠军资格。它们不能互相代替。

| 维度 | 推荐观察内容 |
| --- | --- |
| Alpha 倾向 | 大牌购入覆盖率、首次购入时点、固定 Main 时点的得分轨迹、大牌印刷分。 |
| Beta 倾向 | 相对匹配 Balance 参照的 0–1 VP 购牌行为、投资兑现时点、贵族覆盖和得分效率。 |
| Balance / 混合 | 没有清晰单一路线时，标为混合或暂定；不要把“其他两类不显著”当作均衡已验证。 |
| 归类置信度 | 变化幅度、配对不确定性、跨对手与座位的一致程度。 |

**风格是一组相对指标，不必强压成单个总分。** 路线可以暂定，也可以同时呈现多个倾向。默认冠军需要竞争证据；研究分支可以保留有价值但尚未胜出的模型。

尤其要区分“父代比较”和“风格参照比较”。M67 的父代是 Prism Alpha v0.1.5；比它多买小牌，仍不自动等于比 Balance 更偏基建。

购牌数量也受市场机会和对手阻挡影响。建议复用保存局面，比较两种牌都可买时的动作概率与选择。没有这种机会时的少买，不能直接解释成策略不喜欢。M62 曾有同局面诊断，但高 VP 可购状态覆盖很少，不能据此概括整体偏好。

## F 推荐研发流程：少改一轮，多回答一个明确问题

```flow
研究问题 -> 小预算多种子探索: 预先固定预算
小预算多种子探索 -> 候选冻结: 只用开发证据选择
候选冻结 -> 独立实战确认: 新种子与代表对手
独立实战确认 -> 实战价值结论
独立实战确认 -> 行为画像与路线建议
实战价值结论 -> 发布决策
行为画像与路线建议 -> 发布决策
```

**三条研发工作并存，但不要求每轮都同时开训：**

- 棋力主线：胜负驱动，研究跨对手收益是否可重复。
- 风格支线：同父、同预算的受控奖励实验，允许有限竞争代价。
- 系统主线：提升吞吐、存储、恢复和报告可靠性，不混入棋力归因。

每轮尽量只回答一个主要问题。更换奖励、对手池、预算、优化器和架构后，不能把变化统称为“某一个改进有效”。M67 已明确不是 M66 的同预算重复，这个边界是正确的。

## G 建议的执行顺序

**现在：让已授权的 M67 按原合同完成。** 保留两臂的完整结果，即使一臂改善、另一臂没有。不要拿中间检查点替换 c20，不据训练战绩提前分配版本。

**下一次扩量前：做一个有界的工程轮。**

1. 分解阶段耗时，测出存储与累计状态增长。
2. 消除热路径重复全量保存或扫描。
3. 验证崩溃恢复、缺页重渲染与观察器恢复。
4. 给源码与依赖一个可重建的版本快照。

**再下一步：提高研究的信息效率。** 采用多训练种子探索、少量候选独立确认；建立风格画像卡；冻结代表对手及可接受退步范围。风格路线名不必每轮变动，证据足够再调整。

当前工作树有 45 个已跟踪修改，关键的新模型与轮次脚本仍未跟踪。运行清单已有哈希，这是优点，但哈希不等于源码备份。建议按完整工程轮收口提交或保存可验证源码包，不要把所有历史改动一次性混合提交。**本次没有替你提交。**
