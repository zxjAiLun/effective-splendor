## Problem and evidence

M35A produced 1,035 complete verified replays (960 formal + 75
excluded-prefix) across 17 pairings, stored as local run directories.
Replay Studio can only view a replay through an AnalysisTraceV1 sidecar
generated by an analyzer (M13/M07/M23 review), and there is no way to
browse the M35A experiment corpus, select a match by model/opponent/seed,
and step through the boards. Researchers need to see how each historical
neural checkpoint actually played (take/buy/reserve decisions, final
scores) without re-running any experiment.

## Initial design

- A read-only **source registry** (`benchmarks/studio-replay-sources.registry.json`)
  binds the M35A tracked result and the canonical run-directory roots
  under `local-artifacts/`. The registry is the ONLY way the Host learns
  about experiment sources; the API never accepts client-supplied paths.
- The **Studio Host** gains a `/experiment-replays` API:
  - the experiment index lists pairings with status (VALID /
    EXCLUDED_PREFIX / NONTERMINATION);
  - the pairing endpoint lists all 64 scheduled match slots with seed,
    rotation, seats, scores, winner, plies, terminal reason, and
    availability;
  - the bundle endpoint loads one match, re-verifies it with
    `verify_replay_trace()`, and returns a per-ply frontend bundle
    (board, legal actions, recorded action, player view, referee reveal
    behind explicit confirm) plus the public catalog.
- The **frontend** gains an `/experiments` page (three-column: pairings →
  match list → replay board) reusing the shared board/timeline components
  extracted from the existing player (`app/components/replay-board.tsx`,
  `app/components/replay-timeline.tsx`), with candidate-only decision
  navigation, deep links, and visible EXCLUDED_PREFIX / NONTERMINATION
  warnings.
- A **Linux launcher** (`Start Splendor Studio.sh`) starts Host + UI with
  readiness checks, logging, and no double-start.

## Scope and non-goals

- v1 fully supports M35A only.
- No new analysis pipelines, no model evaluation, no Arena execution.
- Original replay/report files are read-only; the Host never writes into
  run directories.
- No arbitrary path acceptance (path-traversal-proof by construction:
  paths are derived from the registry + sanitized identifiers only).

## Contracts and invariants

1. **Read-only sources with verified provenance**: every served replay path
   is derived from the registry's run roots joined with a
   `runs/<eval-id>` or `invalid-attempt-1-<eval-id>` directory and a
   `matches/match-%06d.report.json` / `.replay.json` filename built from a
   checked u32 match index. Client input cannot influence path components
   beyond validated identifiers. The library **fail-closed-verifies at
   load time** that (a) the bound tracked result file exists and its
   SHA-256 equals `tracked_result_sha256`, (b) for every VALID pairing the
   `eval-report.json` exists and its SHA-256 equals `eval_report_sha256`,
   and (c) every run directory, **after canonicalization (symlinks
   followed)**, stays inside the canonical `local-artifacts` root — a
   symlinked run dir pointing outside is rejected at load and again at
   every access. **Every served file** (match report and replay) is
   likewise canonicalized before reading and must resolve inside the
   canonical run directory — file-level symlinks escaping the run dir are
   rejected with their own error, never masked as a missing slot.
2. **Identity binding incl. agent lineup**: a bundle is served only if the
   match report's `game_id` equals the pairing's expected game id, the
   replay's final hash equals the report's `replay_final_hash`, the step
   count equals `completed_plies`, `verify_replay_trace()` accepts the
   whole replay, and **the report's per-seat agent identities match the
   pairing's expected lineup** — with the seat set proven to be exactly
   `{0, 1}` (two distinct records, no duplicates; duplicated
   candidate-seat or opponent-seat records are rejected). M35A neural
   agents report `effective-splendor-m35a-direct-agent-v1` with the model
   id as version; the M07 champion reports
   `effective-splendor-determinization-agent-v1` v1. A wrong-lineup run
   directory is rejected for both match listing and bundles.
3. **Verification before display**: the full replay is re-executed and
   verified on every bundle load; the returned frames are projected from
   the verified referee states (`position.state.observation(actor)`), so
   hidden information (opponent blind reserves, deck order) never enters
   the default player view. Referee reveal is a separate, explicitly
   requested projection.
4. **Scored/prefix separation**: formal 960 matches are labeled `VALID`;
   75 completed-but-excluded prefix matches are labeled
   `EXCLUDED_PREFIX / NOT_SCORED`; the two ply-limit failures are
   `NONTERMINATION / NO REPLAY` entries with no bundle. Prefix matches
   must display a warning and must never be aggregated as formal results.
5. **No mutation**: the Host opens source files read-only and performs no
   writes inside `local-artifacts/m35a-retrospective-arena/`.
6. **Candidate-only navigation is boundary-safe**: stepping past the
   first/last candidate decision keeps the nearest candidate frame — it
   never falls through to an opponent ply (review-repaired), and plain
   keyboard navigation clamps at ply 0 and the last ply.

## Known limitations

- v1 supports M35A only; other milestones' replays are not indexed.
- Bundle loads re-verify the full replay on each request (no cache):
  correct but ~tens of ms per match; acceptable for interactive browsing.
- Excluded-prefix replays are verified only up to their recorded final
  state (the pairing never completed); they are marked NOT_SCORED.
